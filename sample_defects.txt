## DEFECT #1: Incorrect Route Name for Color Change
- **Type:** Incorrect Documentation  
- **Severity:** High  
- **Description:** README documents `POST /change_color/<index>` but the actual endpoint is `POST /update_color/<index>`.  
- **Impact:** Users will get 404 errors if they follow the documentation.  
- **Evidence:**  
  ```
  POST /change_color/0 -> 404 Not Found
  Correct: POST /update_color/0 -> 200 OK
  ```

---

## DEFECT #2: Incorrect HTTP Method for Archive
- **Type:** Incorrect Documentation  
- **Severity:** High  
- **Description:** README states `POST /archive/<index>`, but the implementation only accepts GET.  
- **Impact:** Users attempting POST will receive 405 Method Not Allowed.  
- **Evidence:**  
  ```
  POST /archive/0 -> 405 Method Not Allowed
  GET /archive/0 -> 302 Redirect
  ```

## DEFECT #3: Missing Documentation for Color Parameter in Add Task
- **Type:** Missing Documentation  
- **Severity:** Medium  
- **Description:** `/add` endpoint accepts optional `color` parameter (default `'white'`), but README only mentions `title`.  
- **Impact:** Users unaware they can specify task colors.  
- **Evidence:**  
  ```
  POST /add with title=Task, color=red -> task created with color red
  POST /add with title=Task2 -> task created with color white
  ```

## DEFECT #6: Incomplete Installation Instructions for Windows
- **Type:** Outdated/Incomplete Documentation  
- **Severity:** Low  
- **Description:** README uses `source .venv/bin/activate` (Unix), which fails on Windows PowerShell.  
- **Impact:** Windows users cannot activate virtual environment using documented command.  
- **Correct Commands for Windows PowerShell:**  
  ```powershell
  .\.venv\Scripts\Activate.ps1
  ```
  **Alternative for Windows CMD:**  
  ```cmd
  .\venv\Scripts\activate.bat
  ```
